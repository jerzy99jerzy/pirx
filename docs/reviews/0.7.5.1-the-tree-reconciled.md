## Found, not fixed

- **F65** - a grant file that does not parse ends the pump. `Gate.handle`
  promises never to raise a refusal at its caller, but reads the grant file
  outside its refusal boundary. With an empty file under `grants/` - what an
  interrupted `write_bytes` leaves - `MalformedGrantRefusal` escapes to the
  pump, which records it, exits 3, and answers neither that call nor any
  after it (no reply to either of two frames) [measured against 8a0d0eb].
  The pump's handler is marked `pragma: no cover - gate.handle catches its
  own`, so coverage hid the path its comment calls unreachable. Nothing is
  forwarded; the harm is a session killed by a file, the class A45b defends
  against. Reachable without an attacker: `gate-approve` writes grant files
  non-atomically and before `grant.issued`, so a crash between the two also
  leaves a spendable grant with no issuance record, against MANUAL 8.4's
  "absence is evidence" [inference, by reading]. Owner: 0.7.6.0 (TODO). Not
  fixed here because it changes what the gate does, for a reason unrelated
  to documentation - the argument that deferred F64 at 0.7.5.0.
- **F66** - `approval.decided` has two shapes. The runner records
  `challenge_passed` and `floor_seconds`; `gate-approve` records neither
  [measured, by reading]. The manual now says so and names the
  `gate.pending` field the floor can be recomputed from. Owner: 0.8.0.0, the
  report that reads both surfaces (TODO).

# Pre-push review: 0.2.0.0 hostile-agent harness

```
Document:     docs/reviews/0.2.0.0-hostile-harness.md
Scope:        pirx/session.py, pirx/cli.py, tests/harness/, tests/test_no_capabilities.py
Disposition:  per finding - fixed / accepted with reasons / deferred
```

## F6 - CI supply chain: actions pinned to moving tags - **fixed**

`actions/checkout@v4` and `actions/setup-python@v5` are mutable references.
Whoever controls those repositories - or whoever takes over that control -
can move the tag and execute arbitrary code in this pipeline. Leaving that in
a project whose register says *trust does not cross a boundary because the
same person wrote both sides* was an inconsistency, and a public repository
raises the value of the target.

Fixed: both actions pinned to commit SHAs with the release recorded in a
trailing comment, and `permissions: contents: read` declared at workflow
level so `GITHUB_TOKEN` is scoped regardless of organisation defaults.

Residual, named: pinning freezes security patches too. Refreshing pins is a
deliberate act, and the version comment exists so a reader can tell how stale
a pin is. No automation for it, by choice - a bot that rewrites the pipeline
is the thing the pin defends against.

## F7 - Recording refusals required a catch, which the old scrape forbade -
**fixed by sharpening the rule**

`session.py` needs to write refusal events, which means catching a `Refusal`.
The 0.1.0.0 scrape said *only the runner may catch*, which would have made
the correct design fail the build. The blunt rule was a proxy; the property
that matters is that control flow still terminates at the caller.

Sharpened: a handler outside the runner may catch a `Refusal` **only if its
last statement is a bare `raise`**. A second test asserts that exactly one
module (`cli.py`) ends a refusal's life, so "where do refusals go" keeps one
answer. Strictly stronger than what it replaced: it now also catches a
swallowing handler inside a module the old rule would have allowed by
omission.

## F8 - Scrape could not tell a read from a write - **fixed** (closes F5)

F5 accepted `cli.py` in the file-write allowlist because the call-name scrape
flagged `read_bytes` alongside `write_bytes`. That is the failure mode where
an allowlist grows to accommodate a weak check. The scrape now inspects
`open()` mode arguments, handling the builtin form and the `Path` method form
separately, and **fails closed** on an unresolvable mode. `cli.py` is out of
the allowlist; only `ledger.py` remains. The distinguishing capability itself
is tested, because an allowlist narrowed on the strength of an unverified
check is worse than a wide one honestly labelled.

## F9 - A harness that passes on first run proves nothing - **addressed by
mutation testing**

All 90 tests were green the first time the harness ran, which is exactly when
a verification vehicle deserves suspicion. Three mutants were introduced and
the harness observed failing:

1. **Single-use disabled** (`if False and grant.nonce in self._spent`) - A05
   went red. The control is load-bearing.
2. **Refusals raised but not recorded** (`_record_refusal` returns `None`) -
   seven attacks went red *while the exceptions still raised correctly*. This
   is the one that matters: it proves the harness asserts on the ledger the
   product wrote, not on the exception, which is the claim ARCHITECTURE A9
   makes and which would otherwise have been an assertion about a test.
3. **Budget consumed out of ranking order** - A14 plus three unit tests went
   red, including the P1-starvation case.

Mutants were reverted and the full gate re-run clean. Not automated: a
mutation-testing tool over the whole suite is a candidate for the deferral
table with a future owner, not silent scope.

## F10 - Attack catalogue could drift from the suite - **fixed**

A catalogue claiming coverage that no longer matches the tests is worse than
no catalogue. `test_every_catalogue_row_has_a_test` parses `CATALOGUE.md`,
asserts fifteen rows, and resolves each named test function in the module.
Adding a row without a test, or renaming a test, fails the build.

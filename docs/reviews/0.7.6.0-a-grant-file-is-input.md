## F65, closed: what was wrong

Found by the 0.7.5.1 diagram review, not by a test: redrawn from
`Gate.handle`, the gate's data path put one read outside the refusal
boundary the docstring promised.

- **The escape** [measured against 8a0d0eb]. With an empty file at
  `grants/HASH.json`, `Gate.handle` raised `MalformedGrantRefusal`. The pump
  caught it in a handler marked `pragma: no cover - gate.handle catches its
  own`, recorded it, and exited 3 without answering that frame or the next.
  Nothing was forwarded; the harm was a session ended by a file, the class
  A45b defends against, behind a comment that told coverage the path did not
  exist.
- **Where the file came from** [by reading]. `gate-approve` wrote grant
  files with a plain `write_bytes`, so an interrupted write could leave
  exactly that empty file.
- **The order** [by reading]. It wrote the file before appending
  `grant.issued`, so a crash between the two left a spendable grant with no
  issuance record, against MANUAL 8.4's "absence is evidence".
- **Unmeasured** [measured]. No test drove `approve_pending`; the gate's
  attacks wrote grant files directly, so the walk's event order had never
  been asserted.

## What changed

- `Gate.handle` reads the grant inside its refusal boundary. An unparseable
  file is refused as `refusal.malformed_grant`, answered as a JSON-RPC
  error, and the session continues. `find_grant` reads once, with no
  existence check to race.
- `gate-approve` appends `grant.issued`, then writes the grant to a hidden
  sibling, fsyncs it, and renames it over the final name. The gate reads by
  exact name, so it never sees a partial grant from this writer.
- The pump's handler for an escaped refusal keeps its behaviour - exit 3, on
  the record - and loses `pragma: no cover`: a test now drives it.

Five of six killed. M2 survives, as expected: a file removed between
`exists()` and `read_bytes()` needs another process inside a two-syscall
window, and staging that in a test needs a seam the design does not admit.
The one-read form closes the window by construction and is stated as a
structural fix, not a measured one (P7).

## Deliberately not done

- **Re-presenting a proposal whose grant file is broken.** The walk still
  skips any proposal with a file at the grant path. Since 0.7.6.0 the walk
  cannot leave a broken file itself, so one came from an older version or
  from outside Pirx, and the manual says to remove it. Replacing it silently
  would make the approver the repair tool for a file nobody explained.
- **A directory fsync after the rename.** A grant lost to a power cut after
  the rename leaves a record without authority, the safe direction. The
  spend store syncs its directory because a lost spend record is a replay
  window; a lost grant is not.

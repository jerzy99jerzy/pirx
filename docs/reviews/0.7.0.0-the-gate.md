# Review: 0.7.0.0 - the gate, and three format changes

```
Document:     docs/reviews/0.7.0.0-the-gate.md
Scope:        pirx/mcp/, gate_approve.py, spendstore.py, the HMAC grant, the
              two schema bumps, PT16-PT20, ARCHITECTURE's overdue body, and
              the research note that preceded all of it
Occasion:     pre-push review of the sprint
Disposition:  per finding - fixed / accepted with reasons / deferred
Version:      0.7.0.0
```

The largest version this project has shipped, and the first that breaks its
own formats. The claim is narrow and should be read against what it does not
say: **a high-impact MCP tool call is forwarded only after a human approved
the exact bytes that describe it, and the record of that is verifiable in a
process that did not produce it.**

Gate: ruff 0, mypy strict over `pirx/` 0, 189 tests, docs audit clean.

## F45 - A static check was written that looked stronger than it was -
**removed, deliberately**

While widening the scrape's terminal-catch-site allowlist for the gate, a new
test was added asserting that every terminal handler body calls a recorder.
It failed honestly and for the right reason: in `cli.py` the refusal is
usually recorded *inside* `session` before it ever reaches the handler, and in
`pirx verify` there is no ledger to record into - the ledger is the thing that
failed. Tuning the regex until it passed would have shipped a check whose
name promised more than its body delivered, which is the exact defect P7 is
about. It was removed and replaced with a comment naming the harness attacks
that measure the property where it *can* be measured (A31, A32, A37, A39,
A40). A check that looks stronger than it is costs more than no check.

## F46 - The write allowlist tripled in one version - **accepted, with the
rule restated rather than widened**

`spendstore.py`, `mcp/gate.py`, and `gate_approve.py` joined `ledger.py`. An
allowlist that grows threefold in a version deserves suspicion, so the rule
it enforces is restated in the constant itself: **no module reaches a system
Pirx acts upon without a grant.** A durable spend record, a pending-proposal
queue, and a grant file are not target systems. A future entry that *is* one
is a finding, not a widening.

## F47 - Expiry moved to the wall clock - **accepted, cost named**

A monotonic deadline is meaningless in a process that did not issue the
grant, so a cross-process grant must carry one its reader can evaluate. The
exposure is real: an operator who moves the system clock backwards extends a
grant's life. It is smaller than a deadline no reader can check at all, and
it is now a line in PT4 rather than a silence. The same paragraph names the
second cost - a grant is a copyable artefact, and nothing in the design
assumes the file is secret.

## F48 - The order inside `spend` changed, and one test was asserting the old
order - **fixed by asserting the control instead**

`spend` now verifies the MAC first (an unverified grant's other fields mean
nothing), then coverage, target, deadline, and only then burns the nonce. A
test previously asserted that a spent-and-expired grant reports the *replay*;
under the new order it reports expiry, because the deadline check runs before
the store is touched. The test now asserts that something refuses and that a
second burn is impossible, which is the control; the exception ordering was
an implementation detail dressed as one.

## F49 - `gate_approve` needs a `RenderedProposal` and must not rebuild one -
**fixed by parsing the bytes**

The attention challenge reads deterministic fields off a proposal, but the
approval process holds only canonical bytes from a file. Reconstructing a
proposal from parts would create a second rendering path - two constructions
of one artefact, which is the divergence P10 exists to refuse. Instead the
fields are parsed back **out of the canonical bytes themselves**, and the
recomputed hash is compared to the one the gate recorded, so a pending file
edited between writing and reading fails rather than being approved
(ARCHITECTURE A21).

## F50 - ARCHITECTURE had been stale for four versions - **fixed**

The document's body stopped at 0.3.0.0 while its decision table kept
growing, which meant its most load-bearing paragraph (§1.1, "one process, one
run") was actively false from the version that split approval from execution.
Sections 5A-5D now cover 0.4.0.0 through 0.7.0.0, §1.1 describes both
topologies and names what the split cost, and the cross-sprint invariants
gained the two the gate introduces. Owner's flag, not a self-audit find: the
document had never been asserted against by the docs audit, and this review
does not claim otherwise.

## Improvements deliberately not taken

- **Deleting the `/1` ledger reader** once `/2` writes: rejected. Retiring a
  writer is not retiring a reader (P8), and an old ledger that cannot be
  verified is an audit trail that expired quietly.
- **Using MRTR to carry the approval prompt**: rejected, and it is now a
  threat row. It is the obvious implementation, which is exactly why PT17
  exists and why A38 asserts the ticket carries no approval surface.
- **A policy engine at the gate** ("gate DELETE, pass SELECT"): rejected.
  That market is funded and taken; the gated registry stays a reviewed-in-code
  list, and the only thing this project sells is the evidentiary quality of
  one approval.
- **Shipping a Windows launcher**: deferred with its research done. The
  research established that the macOS strength claim does not transfer, so
  writing the artefact first and discovering that later would have been the
  wrong order.

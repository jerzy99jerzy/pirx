# Review: 0.7.0.1 - full code review of the gate, and family convergence

```
Document:     docs/reviews/0.7.0.1-code-review.md
Scope:        a fresh read of every module added or changed in 0.7.0.0
              (mcp/, gate_approve, spendstore, grant, justification), plus
              documentation convergence against cve-digest read at source
Occasion:     requested full review one version after the gate shipped
Disposition:  per finding - fixed / documented / accepted
Version:      0.7.0.1
```

The gate shipped green and tested, so this review looked for the class of
defect tests do not catch on their own: a control that binds less than it
appears to, an invariant held by luck rather than by construction, and an
attack the harness did not think to make. Three of those turned up. None was
exploitable as shipped; all three were the shape the family's own practices
exist to refuse, which is why they are fixed rather than noted.

Gate after the review: ruff 0, mypy strict 0, **192 tests** (189 + 3), docs
audit clean. The three new tests are the two F51 regressions and attack A43.

## F51 - `gate_approve._reconstruct` was lossy and relied on an unstated
invariant - **fixed**

The approval surface rebuilds a `RenderedProposal` from a pending file so the
attention challenge has a proposal to read fields off. It dropped `params`
(`params={}`) and reconstructed only `action`, `target`, and the three
justification head fields. That was safe **only** because none of the three
challengeable fields (`target`, `justification`, `action`) is a param - an
invariant that lived nowhere, was tested nowhere, and would have broken
silently the day `CHALLENGE_FIELDS` gained a param-derived entry, desyncing
what the challenge asks from what the human is shown.

Fixed by parsing every `param.*` and `justification.*` line back, and by
re-rendering the rebuilt proposal and refusing if it does not reproduce the
pending bytes exactly. The invariant is no longer load-bearing: a challenge on
any rendered line now reads the same value the human sees, by construction.
Two regression tests round-trip a real gate proposal and reject tampered
bytes.

## F52 - `grant.justification` is in the MAC scope but re-checked nowhere -
**documented, deliberately not "fixed"**

`spend` verifies the MAC, then re-checks `action_hash` and `target`, but not
`justification`. At first read that looks like a control with a gap. It is
not: `justification.ref` renders into the preimage, so `action_hash` already
binds it, and the only caller holding a ref to compare against is the renderer
that produced the hash - an independent check would compare the field to a
value derived from the same bytes it was hashed from, a tautology wearing a
control's clothes (P7). `target` is re-checked as a readable assertion despite
being equally bound; `justification` is not, and the asymmetry is now
explained in the `spend` docstring rather than left for the next reader to
mistake for an oversight. The field stays in the scope because removing it
from MAC coverage is the change that would need justifying.

## F53 - field-line forgery via intercepted-call arguments was uncovered -
**fixed by adding A43**

`test_prose_cannot_forge_a_field_line` guards producer prose against forging a
`field: value` line in the canonical rendering. The intercepted-call path
introduced a second source of attacker-influenced text - the tool arguments -
and nothing guarded it. It is in fact safe: `canonical_arguments` serialises
with `json.dumps`, which escapes newlines to `\n`, so a payload cannot break
onto a second line and impersonate a field. But "safe because json.dumps
happens to escape newlines" is a property that deserves a test, not a
coincidence that deserves trust. A43 asserts it.

## Family convergence (PX-0001)

A full read of cve-digest at `main` surfaced convention drift, now carried as
the first exchange entry rather than fixed by one-sided edits:

- **`docs/` filename casing** diverges (cve-digest lowercase, Pirx uppercase).
  Proposed disposition: accept it. Renaming breaks every internal link and the
  vendored-file version pins; the benefit is cosmetic. Recorded so it is a
  decision, not a rediscovery.
- **Codename blockquote**: cve-digest opens each architecture-tier doc with
  one; Pirx named its codename only in the README. Adopted here in `THESIS`,
  `THREAT-MODEL`, `ARCHITECTURE`.
- **TODO format**: aligned to cve-digest's checklist and status legend, with a
  `### Trigger-owned` subsection Pirx adds and proposes upstream.
- **WORKFLOW.md (F32)** and the **five provenance lines (F35)** fold into
  PX-0001, which now has the concrete substance it was reserved for.

## What this review did not change

- **No behaviour changed.** F51 tightens a reconstruction, F52 is
  documentation, F53 adds a test. The 189 tests from 0.7.0.0 still pass; the
  three additions are new assertions, not adjusted ones.
- **The MAC scope is untouched.** F52 explicitly keeps `justification` in it.
- **No filenames moved.** PX-0001 proposes leaving the casing divergence
  alone, with reasons.

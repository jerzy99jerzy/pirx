## What differs from cve-digest's, and why

- **Diagrams.** cve-digest's manual has none; this one has three (3.1, 3.2,
  8.3). GitHub draws Mermaid with a script, and this page runs none, so each
  block was drawn once into an SVG named for the SHA-256 of its source, with
  mermaid-cli 12.0.0 (mermaid 12.2.0), `-t dark -b '#0d1117'`; the command is
  in the builder's docstring. An edited block without a new drawing fails
  the gate, and a drawing no block names fails a test, so a redraw cannot
  leave a stale picture behind. Labels keep Mermaid's HTML rendering, which
  is how the `<i>` in 3.1 and 3.2 render as italics; with HTML labels off they
  printed as literal tags [measured, by rendering both].
- **SVG checks.** A drawing opened directly runs with the site's origin and
  outside the page's Content-Security-Policy. The builder publishes one only
  if every element and attribute is on an allowlist of exactly what
  mermaid-cli wrote for the three diagrams (a test holds the lists equal to
  what the drawings use), HTML appears only inside a `foreignObject`, the
  bytes hold no `<?` or `<!`, and no value or text, read after the parser
  expands character references, holds a backslash, a `javascript:`,
  `@import`, `@font-face`, `image-set(`, `image(`, `src(`, `expression(` or a
  non-fragment `url(...)`. Mermaid's output for these three diagrams passes;
  a `click` link would not, and should not.
- **Description.** Taken from `pyproject.toml`: the manual opens with an
  epigraph, whose first sentence would describe nothing.
- **Contents.** The manual has its own contents section; the page's
  navigation lists every other `##` and `###` heading, not that one, because
  the navigation is a contents list. The section stays on the page, and a
  test checks each of its links lands on a heading there.
- **The band** takes the banner's own colours: edge `#0d1117`, the letters
  `#cdd9e5`, the subtitle `#788ca5`, and the amber of the status LED
  `#ffb048` as the accent, close to the `#ffb86c` the diagrams use for the
  human. Every
  pair clears WCAG AA, measured by a test. The diagrams sit on the band's
  colour in both schemes.
- **Wide diagrams** keep a minimum width of 40rem and scroll on a narrow
  screen instead of shrinking past legibility.

## Checked, beyond the suite

  Firefox and Safari were not run. That an SVG's HTML labels render inside

## The independent review

A reviewer that had not seen the change written read every line, ran the
suite, re-resolved the action pins, re-downloaded the four packages, and
probed the checks. It found three wrong claims, two misleading ones and
seven minor points; all twelve are fixed in this version.

- **Wrong: the SVG check.** It was a list of dangers, and the reviewer built
  drawings that passed it: a stylesheet processing instruction, which the XML
  parser drops before the tree is read; `<set>` and `<animate>` rewriting an
  `href`; HTML inside a `foreignObject` that fetches (`object data=`, `img
  srcset=`, `meta http-equiv=refresh`); CSS `image-set(` and a CSS-escaped
  `url`; an `@import` in a tail the scan never read. It also noted, by
  reading the code, that `javascript:` split by a tab would pass. Whether a
  browser would have fetched or run each is [inference]; none was opened in
  one. The check is now an allowlist, and each form is a test
  case. Three documents had described the old check as stopping everything
  that executes or fetches; they now describe what it checks.
- **Wrong: the token test.** It missed `id-token: write` followed by a
  comment, and `permissions: write-all`, which includes `id-token`. Both are
  matched now, with a test of each form, and each Pages job's permissions are
  pinned exactly.
- **Wrong: the accent colour** was said to be the diagrams' colour for the
  human. It is the banner's LED, `#ffb048`; the diagrams use `#ffb86c`.
- **Misleading: the parser's reach.** PT22 said a compromised parser could
  not reach `main`. In the gate's test job it runs inside the process that
  produces the required `pytest` verdict, so it could turn that check green.
  PT22 says so now.
- **Misleading: "each refusal is pinned."** Four refusals had no test (a query
  string, a protocol-relative link, a heading with no text, no title); they
  have one each now.
- **Minor: "Mermaid's own output passes."** A `click` link is refused,
  correctly; the claim is narrowed to these three diagrams.
- **Minor, fixed:** the paths test read GitHub's filter with `fnmatch`, where
  `*` crosses `/`; it now reads it as GitHub does. A diagram test hard-coded
  a line number; it computes it. The slug rule claimed github-slugger
  exactly; it is exact for ASCII headings, which are all the manual has. The
  determinism test built twice in one process; it builds in two with
  different hash seeds. One PT22 line was over the column.

A second pass by the same reviewer, against the fixes, found one more wrong
point and four minor ones, all fixed here:

- **Wrong: a backslash as a character reference.** The backslash refusal
  read the raw bytes, and `&#92;` or `&#x5c;` is a backslash only after the
  parser expands it, so `u&#92;72l(` in a stylesheet or a `style` attribute
  passed and reads as `url(` to CSS [inference: the fetch was not observed
  in a browser]. The backslash is now refused in every parsed value, text
  and tail, which also covers a literal one, so the raw-byte check for it
  was removed as dead.
- **Minor:** `expression(` and both namespace checks had no test; they have
  one each. `src(` and `image(` take a URL without `url(` and were on no list;
  as far as the reviewer knew no browser fetches through either [inference],
  and both are refused now. This section's own claim that the reviewer had
  built the tab case was wrong; it was read from the code. The TODO entry
  for this version left out the value checks.

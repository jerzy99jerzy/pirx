What this version claims, so the review has something to measure against: **a
grant is unreachable without evidence that the approver operated on the exact
hashed bytes.** Operated on, not understood - the residual is named in PT15
and repeated wherever the wording could inflate.

Verification vehicle checked before being trusted: four targeted mutants
(transcription comparison removed at the surface; floor check removed at the
surface; attention verification removed at the issuer; session-budget check
removed at the issuer), each killed by unit tests **and** by harness attacks,
`__pycache__` cleared between runs (F14 discipline). The restored tree is
green: ruff, mypy strict over `pirx/`, 156 tests, docs audit.

## F36 - The draft design collided with an existing assumption id - **fixed**

The gate design draft (and the first cut of this sprint's docstrings) cited
"ARCHITECTURE A13" for surface-measures/issuer-enforces. A13 was already
taken (KNOWN_INTENTS, review F3). The new assumption landed as A17 and every
reference was repointed. Same defect class as the draft's stale brief-version
references (written against v1.2, repo held v1.3): a document authored
outside the repository asserted repository state from memory. Both corrected
at vendoring time; the pattern is the 0.4.0.2 review's pattern and the
remedy is the same - read the tree, then write.

## F37 - The session grant budget cannot fire in this topology - **accepted
with reasons, named in three places**

`MAX_GRANTS_PER_SESSION` (20) exceeds `MAX_PROPOSALS_PER_RUN` (10), and one
run is one issuer, so in 0.5.0.0 the PT13 proposal budget always binds
first. A control that cannot fire is normally a P7 violation - a claim
without a measurement. Disposition: the primitive is real, attacked at the
issuer boundary (A34, plus the unit pair including the refusals-are-free
property), and its production bite is explicitly owned by the long-lived
gate surface at 0.7.0.0. The topology note appears in `types.py`, PT15, and
the A34 docstring, so the acceptance costs a deliberate edit to forget.

## F38 - The challenge is beatable by tooling - **accepted with reasons**

An approver who pipes the rendered bytes through a script answers every
challenge without reading. PT15 says so verbatim rather than hedging: the
control forces the bytes through something the approver operates, and the
ledger's latency distribution makes the pattern visible to an auditor.
Claiming more would be the theatre this sprint exists to refuse. The
fatigue-signal report that surfaces such patterns is owned (T8, 0.8.0.0).

## F39 - A33's validity depends on the two expected answers differing -
**fixed by construction**

The cached-answer replay attack is vacuous if proposal 2's challenged value
happens to equal proposal 1's. The attack asserts that precondition
explicitly, so a renderer or hash change that makes the answers coincide
fails the attack loudly for re-authoring instead of passing it while it
measures nothing. Recorded in the catalogue prose as well.

## F40 - `decide` refuses without a decision object, which moved recording
to the runner - **accepted with reasons**

Challenge and floor refusals leave no `ApprovalDecision` behind, so the
surface cannot hand the session anything to record; `cli.run` catches the
typed refusal and records it via `Session.refused`. This is the sanctioned
top-level catcher, not suppression (P11), and A32 asserts the ordering the
design promises: `attention.challenge_issued` precedes
`refusal.challenge_failed` in the ledger, intent before outcome (PT9
discipline). The alternative - a decision object carrying "refused" - would
have made a refusal representable as a decision, which is the boolean-approval
shape the thesis rejects.

## Improvements deliberately not taken

- A per-proposal retry counter on the challenge: rejected. A failed
  challenge restarts the presentation from the top; a retry counter is a
  grind surface.
- Randomising the challenge field per presentation: rejected. Hash-selection
  is already unpredictable before the bytes exist, and determinism keeps
  "same proposal, same challenge" auditable after the fact.
- Floor-checking declines: rejected, and the register in `approve.py` says
  why - refusing fast is not the threat.

## Found at the landing

- **The 0.7.2.2 review was wrong about a phrase.** It says "sink discipline"
  "does occur in cve-digest - in `obs.py`". The phrase occurs nowhere in
  cve-digest's history before 0.7.18.1 (`git log 786efcd -i -S'sink
  discipline'` in a cve-digest clone finds no commit); what `obs.py` has is a
  durable-sink section describing the discipline. The review is a record and
  stays as written; this one corrects it. P11's strike stands, and FAMILY.md's
  wording, which describes the discipline rather than quoting a phrase, needs
  no change.
- **PX-0001's `origin:` line moved.** It read 0.7.0.1 when the entry was
  first written (`8b7d9e1`), a version the tree never declared: it went from
  0.7.0.0 to 0.7.0.2. The carry commit (`6efc805`) moved it to 0.7.2.2, and
  cve-digest's mirror carries 0.7.2.1, the version it was written at. Left as
  it is: the mirror's landing section now cites 0.7.2.2, and changing the line
  would make that citation stale for no gain. FAMILY.md 3.3 does not say an
  origin line is written once; that is owned by the next FAMILY.md amendment,
  with the next item.
- **An orphaned deferral.** `docs/PIRX-GATE-DESIGN.md` records a "B2
  named-trigger amendment" as travelling to FAMILY's canonical home. It never
  travelled, nothing owned it, and B2 is defined nowhere in this tree. It is
  owned now by the same trigger in `docs/TODO.md`.
- **Half of the tolerance is untested.** The rule cve-digest accepted covers
  the whole payload. `consumer.parse` ignores unknown top-level keys by
  construction, reading the ones it knows with `.get`, but only the
  verdict-level half has a test. Owned by the next version that changes
  `pirx/consumer.py`.
- **The transfer check was too loose.** A grep of the downloads directory for
  the version prefix, the form this document used, listed four files for a
  two-patch pair on the cve-digest crossing, because two review diffs of the
  same version sat beside it [maintainer's terminal]. MERGE-PROCEDURE 1.3
  lists `*.patch` files.

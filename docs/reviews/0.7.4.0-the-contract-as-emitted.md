## What changed, and what did not

**Accepted now that was refused before:** `vex_status: "none"`, and `score`
above 100.0. Both are in cve-digest's published schema and have been since it
was published; `none` is the producer's value for a CVE without a VEX
statement, and KEV items score from 100.0 upward. Pirx refused a whole payload
for either one, so the verdict path had never accepted a realistic run. The
0.7.3.1 review records how that went unseen: the field table came from the
brief's prose and every fixture was written by hand.

**Refused now that could not arise before:** non-finite numbers. JSON parsing
admits `NaN` and `Infinity`. `NaN` was always refused, because it fails every
comparison, and `Infinity` was refused by the old ceiling. Removing the
ceiling would have let `Infinity` into a rendered byte, so an explicit
`math.isfinite` lands in the same change as the bound it replaces rather than
after it.

**Read now:** `epss_pending`, optional. Absent is read as false, which is what
every payload before cve-digest 0.7.18.0 meant. True requires `epss` to be
0.0, the same shape as `cvss_pending` forbidding a CVSS value. It then renders
as `epss: pending` in the evidence bytes and the proposal parameters, and as
`null` in the model prompt, exactly as a pending CVSS already did.

**Not moved:** the evidence bytes for a published score. They are now held as
a golden literal captured from 0.7.3.1 before the change, because the evidence
digest is inside the action hash. Rendering `pending` on a separate line would
have changed every verdict's bytes and needed `pirx.proposal/3`. Replacing the
value on the existing line changes only the bytes of pending items, whose
previous rendering was a zero the producer had documented as not a
measurement. No grant can have been issued against those bytes in practice,
since no real payload was ever accepted (F62).

**Tolerated, and now tested:** unknown keys. The producer's additive changes
rely on consumers ignoring them, and the consumer did, by construction and
without a test. A marker in an unknown key and in `tickets` is asserted absent
from the evidence and the parameters.

## The fixture

`tests/fixtures/verdict-1.cve-digest-0.7.18.0.json` was produced by
cve-digest's own `verdict.build_verdicts` at `786efcd`, from synthetic scored
inputs (one KEV item with no VEX statement, one EPSS-pending item, one
ordinary item), and carried into this tree by hand. Its inputs are synthetic;
its shape is the emitter's. It is the first thing in the suite that Pirx did
not write about itself. Refreshing it is a human act at exchange time, like
every other crossing.

## PX-0003

The producer-side half of F63 is not Pirx's to fix. The verdict object is
published with `additionalProperties: false`; a payload from 0.7.18.0 fails
strict validation against the schema as published on 2026-08-06, measured with
`jsonschema`. That meets the schema's own stated test for a breaking change.
Pirx does not validate against the JSON Schema and is unaffected. The entry
asks cve-digest to pick a rule, and travels with the PX-0001 mirror.

## Deliberately not done

- **Validating against the producer's JSON Schema.** It would make Pirx the
  strict consumer PX-0003 describes and break on every additive change, and
  it would add a runtime dependency to a project that has none.
- **Reading `epss_percentile`.** Nothing in Pirx orders or renders by it.
  Ignoring a field is not a promise to use it.
- **Replacing `examples/verdict-sample.json`.** It stays as a readable
  example; the producer-emitted fixture is what the tests trust.

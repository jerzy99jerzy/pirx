## What the exercise was supposed to produce

PX-0001 was reserved at 0.1.0.0 and referenced in four documents before it
existed. Its stated substance was small: confirm or strike five provenance
lines, and settle whether Pirx vendors cve-digest's WORKFLOW.md. The honest
expectation was five confirmations and a filing decision.

## What it actually produced

**Four confirmations, one strike, and one structural finding nobody was
looking for.**

The four confirmations are worth exactly what they cost: P2's negative-space
docstrings exist (`delivery.py`, `identity.py`, `verdict.py`), P6's ranking
weights are module literals with no config path (`estate.WEIGHTS`,
`vex.VEX_WEIGHTS`), P8's contract discipline is stated in `verdict.py` and
demonstrated by `attach_tickets` keeping the id through an additive change,
and WORKFLOW.md exists upstream at doc version 1.6. Each now names the module
that carries the evidence instead of naming a repository.

**The strike is P11.** FAMILY.md credited the practice "refusal is an event,
never a warning" partly to "Rappaport's sink discipline". That phrase does
occur in cve-digest - in `obs.py`, about logging handlers, redaction, and
keeping an audit artefact distinct from console display. It is a real
discipline and it is not this one. cve-digest's `notices` are `list[str]`:
prose for a human reader, not typed events, and not refusals. The attribution
was built on a shared word rather than a shared mechanism, and it has been in
the family's shared document since it was written.

## F58 - FAMILY.md named a canonical home that does not exist

The header read:

```
Canonical home: cve-digest, docs/FAMILY.md
Vendored by:    pirx, docs/FAMILY.md  (verbatim, version pinned in this header)
Amended via:    the exchange protocol in section 3, never by direct edit
                in a vendored copy
```

`find . -iname "*family*"` in cve-digest at `main` returns nothing. There is
no `docs/exchange/` there either.

So the document defining the family's practices and its exchange protocol
described itself as a vendored copy when it was the only copy, forbade direct
edits in favour of amending a home that is absent, and named a protocol whose
destination directory did not exist on the other side - a fact discovered
only because an entry finally needed somewhere to land.

Nothing in either codebase was broken by this. What was broken was a claim, in
the one document whose purpose is to keep two projects honest with each other,
and it survived four versions because nobody had cause to look.

The header now says `UNRESOLVED` and points at PX-0001 item 5, with a dated
correction note in the body. **It is deliberately not "fixed" here**: choosing
between creating the canonical copy upstream and naming Pirx the home is a
family decision, and making it unilaterally inside the vendored copy would
repeat the exact error - editing the shared document from one side.

## Why this belongs in a review rather than a quiet edit

The instruction for this session was to stop logging every mitigated mistake
in detail, and that is right for slips that were caught and fixed inside one
sprint. This is a different class: a false claim that survived four versions
in the family's shared contract, found by the first process designed to find
it. The protocol earned its keep on its first use, and a review that omitted
that would be selling the process short.

## Deliberately not done

- **Creating `docs/FAMILY.md` in cve-digest from here**: rejected. A
  human-carried protocol whose first act is one repository writing into the
  other is not a human-carried protocol.
- **Deleting the P11 practice**: rejected. Only the attribution was wrong; the
  practice is Pirx's own and is enforced by `errors.py` and the scrape.
- **Deciding item 3 or item 6**: rejected. Both are the owner's, and both are
  in the TODO with the decision named rather than a default assumed.

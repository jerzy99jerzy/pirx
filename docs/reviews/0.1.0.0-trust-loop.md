# Pre-push review: 0.1.0.0 trust loop

```
Document:     docs/reviews/0.1.0.0-trust-loop.md
Scope:        all of pirx/ and tests/ as of this version
Disposition:  per finding - fixed / accepted with reasons / deferred
Convention:   inherited from cve-digest (brief section 8)
```

## F1 - Approval frame marker was forgeable by producer prose - **fixed**

Found by `test_framed_region_survives_hostile_prose` on its first run, not by
eyeball. The approval surface framed the canonical bytes with a *fixed*
closing marker; prose containing that marker string made the frame appear to
end before it did. Escaping prevented forging a *field line* but not the
*frame line*, because the frame is written by `approve.py` outside the
escaped region's line-prefix discipline. This is PT6 by content rather than
by byte divergence: the far side of the trust boundary controlled where a
reader believed the approved artefact ended.

Fix: per-presentation random 128-bit boundary, MIME-style, generated after
the prose already exists; `extract_framed` reads the boundary from the first
opening line, which the surface wrote before any prose reached the stream.
Regression test includes a forged-boundary variant.

## F2 - Validation invisible to the type checker - **fixed**

`_require(condition, exc, ...)` performed runtime checks that mypy strict
could not see, forcing `type: ignore` in the parser's hot path - meaning the
class of bug the validation exists for (a wrong-typed value flowing onward)
was invisible to exactly the tool meant to catch it at the desk. Replaced
with narrowing helpers (`_as_bool`, `_as_number`, `_as_enum`, `_as_list`)
that return the checked value. All ignores removed; mypy strict clean.

## F3 - Deviation from ARCHITECTURE.md: action names are a code constant,
not an enum over registry keys - **accepted with reasons**

ARCHITECTURE.md 3.3 specified the proposal's action field as an enum built
from registry keys. With the registry empty (the version's defining
property), that enum is empty and no proposal can be constructed - making the
brief's end-to-end demonstration ("watch the spend be refused") impossible.
Resolution: action names come from the code constant `KNOWN_INTENTS`;
registry membership is checked at spend, which is where refusal belongs in
this version's story. PT2 is unaffected - an action name still never derives
from prose. ARCHITECTURE.md carries this as an amendment at its next bump
(A13), and until then this finding is the record.

## F4 - Environment gap: verified on Python 3.12.3, declared for 3.14 -
**accepted with reasons**

The build container runs Python 3.12.3. All gate results (ruff, mypy strict,
71 tests) are measured on 3.12.3; `requires-python = ">=3.14"` is the
project's declaration and is **unverified in this environment**. No 3.13+
syntax is used. Trigger for closing: first CI run on 3.14 in the GitHub
repository. Stated in README as well, per P7 - a measured claim about what
was measured.

## F5 - `cli.py` in the file-write allowlist - **accepted with reasons**

The scrape allowlists `cli.py` for file operations because the runner reads
the payload (`read_bytes`). Reading is not writing, but the current
call-name scrape cannot tell them apart without argument analysis. Accepted
for 0.1.0.0: the runner contains no write call, reviewable by eye at its
current size. Sharpening the scrape to distinguish read from write call
sites is a candidate improvement owned by 0.2.0.0, where the harness work
touches these tests anyway.

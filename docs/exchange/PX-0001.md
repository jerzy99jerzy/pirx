# PX-0001: documentation convergence across the family

The first exchange entry, referenced as pending since 0.1.0.0 and created now
that there is enough divergence to carry. It bundles four items that all
concern the two repositories reading the same way to a person crossing between
them. None of them changes what either project does; all of them are the kind
of drift FAMILY section 1 says a human catches at exchange time, not a machine.

This file is authored in Pirx because the evidence lives here: a full read of
cve-digest at `main` on 2026-08-08 against Pirx's own docs. cve-digest records
its disposition in its own `docs/exchange/PX-0001.md` mirror, per section 3.1.

## Item 1 - `docs/` filename casing diverges; propose leaving it

**Finding.** cve-digest uses lowercase `docs/` filenames (`architecture.md`,
`threat-model.md`, `mechanisms.md`); Pirx uses uppercase
(`ARCHITECTURE.md`, `THREAT-MODEL.md`). Both repositories keep root-level
documents uppercase (`README.md`, `TODO.md`, `CHANGELOG.md`, `WORKFLOW.md`,
`FAMILY.md`), so the divergence is confined to `docs/`.

**Proposed disposition: accept the divergence, do not normalise.** Renaming
either side breaks every internal link, every `docs/reviews/` reference by
name, and - in Pirx - the vendored-file version pins the docs audit checks.
The cost is real and the benefit is cosmetic. Recorded here so the divergence
is a known decision rather than a thing each repository's next contributor
rediscovers and re-argues. If a future reader wants convergence, the cheap
direction is cve-digest's lowercase, done in one repo with a redirect note,
owned by a version - not a cross-family edit.

## Item 2 - codename blockquote convention, now adopted in Pirx

**Finding.** cve-digest opens each architecture-tier document with a
blockquote naming the codename (Rappaport) and tying it to the discipline the
document enforces. Pirx named its codename (Pirx, Lem's pilot) only in the
README.

**Disposition: applied in Pirx at 0.7.0.1.** `THESIS.md`, `THREAT-MODEL.md`,
and `ARCHITECTURE.md` now carry the parallel blockquote. This is Pirx adopting
cve-digest's convention, so it travels as a note rather than a request; no
change is asked of cve-digest.

## Item 3 - TODO format and status legend, now aligned

**Finding.** cve-digest's `TODO.md` is a checklist with an explicit status
legend (`[ ]` open, `[~]` in progress, `[x]` done, then moved to the
changelog). Pirx's was a table.

**Disposition: applied in Pirx at 0.7.0.1.** Pirx's TODO is now the same
checklist form with the same legend. One deliberate addition Pirx carries that
cve-digest does not: a `### Trigger-owned` subsection, for items whose owner is
a condition rather than a version. **This is the one sub-item that asks
something of cve-digest**: adopt the subsection, or tell Pirx it is
unwelcome, so the two TODO conventions do not fork. Proposed, not applied
across the boundary.

## Item 4 - the two provenance debts this entry was always meant to carry

These predate the convergence work and are the reason PX-0001 was reserved.

- **WORKFLOW.md (F32).** cve-digest holds a real `WORKFLOW.md` at v1.6.
  Confirmed present at `main`. Pirx's brief section 8 records the convention
  but never vendored the file. Proposed: vendor it verbatim with the version
  pinned, per the FAMILY vendoring rule, or state in section 8 that Pirx
  deliberately does not carry it. Either is fine; the current silence is not.
- **The five `[cve-digest: confirm]` lines (F35).** FAMILY.md carries five
  provenance assertions about cve-digest's behaviour that were labelled for
  confirmation. With cve-digest now read directly, they can be resolved.
  Proposed: confirm or strike each against the real repository in the next
  pass, and drop the labels once resolved.
